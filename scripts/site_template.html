This is one round of the demo workload (a fictional courier booking parcels, with a transactional outbox) as PostgreSQL 16 streamed it over a logical replication slot. Each row is one message from the walsender. Its first byte is the message type, highlighted in the bytes. Next to it is what the decoder read, and below are the records the relay delivered with examples/relay.yaml. The capture is the fixture the test suite replays, so the page and the tests always agree.

Things to look for:

  • The booking that was rolled back is not in the stream at all. The server only sends committed transactions, which is why the outbox events below can never describe a change that did not happen.
  • The second update of SC-240002 carries ⟨unchanged TOAST⟩ for the large notes column.
  • Deletes only carry the key columns.
  • The rider event has no outbox table: it is a pg_logical_emit_message inside the transaction.
  • The non-transactional heartbeat arrives before the truncate transaction. The message reports the end of its record, which is the exact position where that transaction's commit starts.

What the relay delivered

Table changes go to swift.cdc.<table> with notes dropped and phone numbers HMAC-masked. Outbox events go to swift.events.<aggregate_type> keyed by aggregate id. sync_scratch is excluded, and the outbox table's own rows are not republished. Ids are <commit LSN>:<position> and are stable across redelivery.
